## Cause and change

The contracts stage copied the whole Docker context and set VONK_BUILD_SOURCE_SHA before installing its environment and generating clients. Every commit reran dependency setup, OpenAPI/TypeScript generation and CLI packaging, separately on amd64 and QEMU arm64. The API and worker already reuse runtime-root on the same builder: the baseline worker takes 51s, not a second 17-minute build. Their two mode=max GHA exporters nevertheless export the common intermediate graph twice. On inspection, Actions cache usage was 11,108,364,236 bytes across 2,596 caches; no API layer was CACHED in the baseline run. Scopes were stable per role, not SHA-specific; BuildKit layer keys include actual COPY inputs, platform, parent layers and consumed build arguments, with DEPENDENCY_DAY intentionally refreshing runtime dependencies daily.

The Dockerfile now generates platform-neutral outputs natively on BUILDPLATFORM, installs locked generator dependencies before source, copies only the import graph and packaging/generator inputs, and embeds the commit SHA in a separate CLI packaging stage. Controller/CLI source is still needed because schema creation imports the real application; web source and Compose assets are excluded. The web bundle also builds natively via node-tools; runtime Python dependencies and skopeo retain their target architecture. The pure-Python CLI wheel remains py3-none-any. Bytecode and node_modules directories themselves are excluded from the context, including their previously retained directory entries.

Both roles read one stable ghcr.io/carstvaartjes/vonk-forge-api:buildcache registry cache; only API exports mode=max (including the shared intermediate graph). Worker reuses the same builder without a duplicate export. Cache is separate from accepted image tags and their existing digest, SBOM, provenance, signature and acceptance checks. The daily dependency refresh remains unchanged. The job timeout returns to 30 minutes.

Docker documents registry mode=max and separate cache/image references: https://docs.docker.com/build/cache/backends/registry/ . Native build stages avoid emulation for architecture-independent generation: https://docs.docker.com/build/building/multi-platform/ .
