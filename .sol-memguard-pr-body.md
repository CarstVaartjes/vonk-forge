GB10 accounting limitation: NVIDIA documents one shared CPU/GPU DRAM pool and special pinned cudaMalloc allocations, but does not promise that all CUDA/driver allocations are charged to cgroup-v2 memory.max:
- https://docs.nvidia.com/dgx/dgx-spark/known-issues.html
- https://docs.nvidia.com/dgx/dgx-spark-porting-guide/porting/cuda.html

Static driver evidence shows that NVIDIA 580.95.05's nv_compute_gfp_mask uses NV_GFP_KERNEL without __GFP_ACCOUNT; the macro is GFP_KERNEL (optionally __GFP_NOWARN). Thus that driver allocation path is not charged to the container memory cgroup. Newer upstream main explicitly adds __GFP_ACCOUNT on kernels >=5.14, so accounting is version/path dependent:
- https://github.com/NVIDIA/open-gpu-kernel-modules/blob/580.95.05/kernel-open/nvidia/nv-vm.c
- https://github.com/NVIDIA/open-gpu-kernel-modules/blob/580.95.05/kernel-open/common/inc/nv-linux.h
- https://github.com/NVIDIA/open-gpu-kernel-modules/blob/main/kernel-open/nvidia/nv-vm.c
