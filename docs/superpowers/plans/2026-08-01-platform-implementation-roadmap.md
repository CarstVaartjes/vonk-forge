# Dual Vonk Forge GPU node Platform Implementation Roadmap

The approved design is implemented in phases. Execute them in order because
each later phase consumes verified artifacts from the preceding phase.

1. **Complete:** [Secure host bootstrap and fabric](2026-08-01-secure-host-bootstrap-and-fabric.md) installed the 1Password public key, repaired cloned identities, inventoried and hardened both GPU nodes, validated their matched platform, checked `earlyoom`, configured the direct one-link/two-function CX-7 fabric, and passed aggregate RDMA, latency, error-counter, and NCCL gates. The as-built result is in the [installation record](../../installation-record.md).
2. **Complete:** [Model profile framework](2026-08-02-model-profile-framework.md) built the developer-machine catalog, adapters, placement rules, fail-to-stopped switching, live node health, and `vonkctl` interface used by every model.
3. **Complete for Mia; DS4 remains verified:** The pinned [Mia DeepSeek 0731 dual-GPU node runtime](2026-08-02-mia-deepseek-dual-runtime.md) passed canonical performance, 15-minute thermal, three-cycle lifecycle, reboot/no-autostart, quality, and release gates and is recorded at `accepted` maturity. The audited [DS4 DeepSeek 0731 single-GPU node runtime](2026-08-03-ds4-deepseek-single-runtime.md) remains `verified`: its pinned Q2-imatrix lane measured below the final single-decode throughput floor and is not advertised as accepted. The `bleysg` DSpark work is tracked as a possible merge into the DS4 branch; it is not a separate model identity.
4. **LLM cataloged; qualification in progress:** The active Phase-4 runtime scope is language and vision-language models: Nemotron, Qwen3-VL, and the newly added Laguna S 2.1 (`laguna-s21-single`). Laguna is a 118B-total/8B-active text-to-text MoE with a 1M context target, and remains `planned` behind its own fail-closed adapter until a GPU node-native image, artifacts, quality, resource, lifecycle, and exact N-way co-residency evidence are produced. The image/3D entries (Qwen Image, Pixal3D, TRELLIS.2, rigging, Step1X-3D, TripoSG, and Hunyuan3D-Omni) remain cataloged for the broader approved design but are explicitly deferred from this LLM-only qualification pass; no unqualified creative endpoint is activatable.
5. **In parallel, without changing active runtime work:** implement the approved [scalable GPU node platform and control-plane design](../specs/2026-08-03-scalable-node-platform-control-plane-design.md). It adds generic per-node onboarding, N-node contracts, and a portable Docker Compose control plane with a shared CLI/web API, Caddy, LiteLLM, PostgreSQL, and observability. Its phased plans must consume—rather than reimplement—the SSH transport and runtime-release interfaces produced by phases 2–4.
6. **Fleet and Library workload plane:** the clean-slate control plane now owns local Fleet/Library desired state and rejects legacy package/deployment operations. New workload runtime changes must use retained Fleet, Library, and Spark-agent helper contracts; only new privileged platform capabilities require a Vonk Forge release.
7. **Release gate:** complete control-plane security, backup/restore, service-host recovery, platform-update skew/rollback, generalized workload-package acceptance, and end-to-end acceptance. At the first real release, enable protected-branch and PR-only repository mutation. The earlier [secondary services plan](2026-08-01-secondary-ai-and-access-services.md) remains historical input, not the current service or model plan.

The model-runtime execution scope remains phases 2–4. Generic onboarding may
proceed independently where its file ownership is disjoint; service-host phases
begin after the Docker-capable host is available. Every phase leaves the system
in a usable, testable state and ends with a commit. Distributed AI profiles
never auto-start after reboot, and no non-AI container is deployed to any
GPU node.
