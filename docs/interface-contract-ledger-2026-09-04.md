# Interface acceptance contract ledger

Baseline: integrated Controller tree `5a58710e` (`Clarify runtime path ownership evidence`).
This ledger records the state of the agreed interface contract at that revision.
An API binding or a passing fixture test is evidence of repository behavior only;
it does not establish publication, deployment, or Spark hardware acceptance.

Status vocabulary:

- **Bound** means the production service, route, and named focused test exist.
- **Partial** means a binding exists but one or more required consumers, states,
  or journeys remain incomplete.
- **Unresolved** means the observable acceptance proof is still missing.

## Evidence boundary and refresh rule

Repository and focused tests establish implementation bindings. Fixture-only
evidence remains explicitly labeled. CI/container checks establish build and
runtime portability only. Controller deployment evidence must name the exact
published source/artifact revisions. Spark hardware evidence must name the
physical nodes, agent/runtime identities, observation time, and operation or
qualification result. None of those boundaries can be inferred from another.

Refresh this ledger after the web, model, cache, telemetry, and distribution
integration pass; preserve unresolved rows until their named journey is run and
its evidence is recorded.
