## Gaps repaired

- Atomic replacement now overwrites the object directly. Previously moving the
  old object into quarantine first briefly removed the serving pathname and
  left a crash window. Existing open readers remain valid through replacement.
- Repair partials use the nested Pydantic `ModelCacheRepairCheckpoint` with a
  persisted per-repair identity. A restart resumes their
  bytes and skips already repaired members; a separate repair starts fresh.
  Admission reserves space for the replacement without deleting the good copy.
- Filesystem digest locks extend deduplication across independent Controller
  workers sharing the NAS root, beyond the previous in-process event map.
- Storage reconciliation reuses the file verifier instead of unconditionally
  hashing every cached payload. Changed identities still trigger verification.
  Unchanged reconciliation also preserves timestamps used by pagination.
- Explicit `check_upstream=true` on the existing updates endpoint checks HF
  repository metadata and returns typed `upstream_revisions`. Ordinary reads
  stay local. The catalog page is snapshotted before releasing its DB session;
  metadata checks then use four shared workers and an eight-second page budget. Accepted catalog updates remain separate from upstream discovery.
