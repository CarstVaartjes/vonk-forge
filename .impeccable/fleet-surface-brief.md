# Fleet operating surface

The first viewport answers three questions without opening a drawer: which Sparks need attention, which models and recipes are running or installed on each Spark, and whether live state matches the selected Fleet Profile.

Use the profile-workload-map composition as the hierarchy reference and the Spark master-detail composition for individual management. Keep Fleet and Library as the only primary destinations; Activity remains an administrative secondary destination. Treat rows and dividers as the normal container. Use graphite and subtle champagne material cues in the shell, but keep dense data on neutral high-contrast surfaces. Green means healthy or the primary safe action, amber means drift or attention, and red means a proven failure. Every profile application begins with a live-versus-desired preview and exposes durable progress.

The matrix is horizontally scrollable at narrow widths and becomes workload-first stacked rows on phones. Preserve loading, retry, empty, disabled, keyboard focus, and reduced-motion states.
